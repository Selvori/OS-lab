# Sv39 不可变模板与分支所有权协议

## 研究判断

在 Seele 的单 owner 调度模型中，让模板在整个分支存活期持有匿名堆原始数据帧。分支持有一个模板引用，只为自己新建或写入后替换的帧承担逐页释放责任。即使第一次写入导致整张末级页表私有化，其中其余借用帧仍由模板保活。这是第 5 步的候选设计。

普通 COW 解决数据内容的写入隔离。On-demand-fork 已经提出按需分离末级表。此处可单独检验的假设是，在相同模板和页表分离条件下，冻结原始帧的所有者能进一步减少帧引用和退出扫描，且节省的时间超过私有页记录、模板驻留的成本。对照模型采用“私有表对每个有效堆帧持引用”的明确规则，仅作为消融实验，不等同于论文实现，也不据此认定原创性。[On-demand-fork 原论文 §3、§5](https://www.cs.purdue.edu/homes/pfonseca/papers/eurosys21-odf.pdf)

## 适用对象及冻结边界

首次原型从自愿冻结的预热任务创建模板，发布后禁止通过模板执行或修改映像。冻结阶段在单 owner 关中断窗口确认匿名私有映射、原始可写性和所有可写别名，准备表树、模板元数据、堆空闲区间及起始用户寄存器映像。若来源仍可执行，须先完成其 COW 写保护或排除其可写别名；可写外部共享映射拒绝冻结。准备失败保留原任务。每个分支以相同快照起跑，根、中层、可变固定映像映射、内核栈与 trapframe 遵循 Seele 的独立分配或原有 COW 规则。文件与 cwd 仍按原引用语义，文件偏移不随内存回滚。第一版仅显式模板派生；分支再次 fork 若尚无转换实现，显式返回不支持，普通进程保留现有 fork。

Sv39 非叶子项的 R/W/X 为零，保护在叶子落实。冻结时对原本可写页清 W 并标明可私有化，RX 保留原权限；提前按现有 Seele 策略确定 A/D 位，避免发布后再改共享 PTE。撤去原有写权限并刷新相应地址翻译后才能发布模板。用户 store 与内核 copyout 共用分离入口，内核经物理别名写用户帧也必须经过该入口。[RISC-V 特权规范](https://docs.riscv.org/reference/isa/_attachments/riscv-privileged.pdf)

## 状态转移与资源释放

| 事件 | 发布后的状态和释放责任 |
| --- | --- |
| 派生 | 活模板加一个分支引用；根及上层链接由分支持有，纯堆末级表借用模板。首表同时包含固定映像，复制 512 项后按现有固定页规则安装对应映射，堆项仍借用。预建非空表目录避免扫描 4096 个堆槽；堆空闲区间复制的代价按实际节点数计。未发布的子分支可整体回滚。 |
| 首写借用页 | 验证原始写权限，预留数据页、必要的私有表及所有权记录；复制旧数据，只在私有末级表安装新帧，再刷新翻译。此槽归分支持有，同表其余借用槽保持原责任。后续写同页直接命中私有映射。 |
| 局部 munmap | 校验整个范围，准备跨表分离和空闲区间节点。提交时仅在私有表清 PTE；借用槽不减模板引用，私有槽在 TLB 刷新后减自有帧引用。重映射同址时安装新零页并登记私有，洞始终以当前 PTE 为准。 |
| 失败与跨页 copyout | 先验证所有页权限并预留全部分离资源，再发布链接、写权限和内容。第二页分配失败则释放本次预留，旧字节、映射、引用数和堆区间均保留。在第一版单 owner 下，提交区间不可被另一个用户地址空间修改者观察。 |
| exec / wait | 成功 exec 安装新地址空间后清理旧分支；失败则保留。普通 exit 仍按 Seele 规则释放文件，wait 在父栈回收地址空间。摘下根中的链接，保证旧地址空间不活动并完成必要的 sfence.vma，回收私有帧和私有表，最后释放模板引用。通用递归销毁器不得递归释放借用表。 |
| 关闭与淘汰 | 关闭模板句柄后拒绝新派生，现有分支继续使用。最后一个引用消失才遍历模板原始映射，释放每个原始持有引用及模板页表。即便所有分支已覆盖某页，只要模板仍活着，该原始页仍占内存。 |

模型用字典保存私有槽。内核首选复用私有末级表，加每表 512 位的自有槽位图（64 B）和私有表目录；借用项从私有表中保留，洞由无效 PTE 表示。销毁每张有位图的表要检查 8 个 64 位字，再遍历置位项。还要释放表页、区间节点与分支根。只读分支销毁工作仍包含这些固定项。原型需记录实际分配粒度和元数据峰值，模型里的零次私有帧释放不能解释为零开销。

## 正确性验收和已执行的验证

两策略使用相同的帧池和输入，与每个分支独立的字典内容逐步比较。每种策略运行 128 个固定种子，每个种子有两个同时存活的分支、30 步交错操作，覆盖写入、局部撤映射、同址重新分配、模板提前关闭、交替退出顺序；在跨相邻末级表的双页更新上逐一注入四个预留失败点。每次检查回滚后的帧与引用，最终检查所有帧回收。另对同一模板重复派生 1、8、64 次并核对每轮余额。模型只执行堆映射与所有权规则；CPU 权限、硬件 TLB、真实分配器、内核代写和 exec 必须在原型上复验。[可执行模型](model.py) · [操作计数](model-results.json)

8 MiB 匿名堆从 0x3000 开始，五个窗口分布为 509、512、512、512、3 页。下表是**模型执行所得操作次数**，两种策略具有相同的表复制量，计数列单位不同，不可相减当作耗时。

| 分支负载 | 两策略复制 PTE 槽数 | 逐项持有策略增加借用帧引用 | 逐项策略退出读取 PTE 槽数 | 模板持有策略退出释放私有帧数 |
| --- | ---: | ---: | ---: | ---: |
| 只读 | 512 | 509 | 512 | 0 |
| 集中写 4 页 | 512 | 509 | 512 | 4 |
| 分散写 4 页 | 2048 | 2045 | 2048 | 4 |
| 全写 2048 页 | 2560 | 2048 | 2560 | 2048 |

分散与集中都只产生 4 个私有帧，前者却多复制 1536 个 PTE 槽。只读场景的部分优势来自混合首表；设置“2 MiB 对齐、纯堆整表”反例时，双方均可整表共享、只读退出均可跳过叶子。模型已实际运行该反例，双方每分支复制 PTE、增加借用帧引用和退出逐槽读取均为 0；该对照应保留到内核实测。每次淘汰两种策略均承担 2048 个原始帧引用释放。每轮写 1 页、共 64 轮时两者都复制 65536 个 PTE 槽，候选策略共释放 64 个分支私有帧，仍须支付模板建立和一次淘汰成本。

## Benchmark 与原型判定标准

选用 Seele 原生 warm 基准作为主测试，便于相同 ELF 在同一台虚拟机复跑。短进程采用 lmbench lat_proc 的 fork+exit 和 fork+exec 两种负载形态，沿用 Seele 的 fork 前至 wait 返回计时；另取 On-demand-fork 的工作集扩张和首次修改成本作为设计依据。此处运行的是 Seele 用户程序。Linux 原版工具的绝对时间不作为门槛。[lmbench lat_proc 手册](https://lmbench.sourceforge.net/man/lat_proc.8.html) · [On-demand-fork 实验](https://www.cs.purdue.edu/homes/pfonseca/papers/eurosys21-odf.pdf)

1. 三种内核路径同条件比较：已交付的 batch-unmap、共同预保护模板加常规逐表共享、同一共享实现加模板所有权。两个模板版本使用同样的初始映像、保护时机、混合首表规则及分离时机。除模板建立与淘汰外，另测一个等工作量的预热父进程循环。避免把一次预热算成每轮节省。
2. 保留原有 11 场景：64 KiB、1 MiB、8 MiB 各只读、集中写 4 页、全写，另加 8 MiB 分散写及立即 exec。增设对齐纯表、跨表撤映射、8 个存活分支分别写同页、一长寿分支拖住模板、同址重映射及内存压力。用具有实际计算的重复任务补充微基准，例如预热只读词典的查询并校验结果散列。报告吞吐、累计驻留页时间和峰值，而不只看 fork 返回。
3. 沿用 2 次预热、3 批各 12 轮、time/counts 分离。摊销另以一次建模、N 次派生与等待、一次关闭至末引用回收为整批计时边界，N 取 1、8、64。主指标为整批时间/N、整轮 P10/中位数/P90；同时保留首次缺页、退出、淘汰、表复制字节、普通帧引用、位图字遍历、峰值及最终余额。对齐场景需以真实 VA 和窗口占用验证。模型不用于预测毫秒数。
4. 功能门槛是所有隔离、RX、copyout 跨页、exec 成败、分配失败、回收余额与已有生命周期回归全部通过。机制门槛是相同写入与表复制量下，减少的逐帧引用和扫描能在内核计数中重现。性能门槛是预先指定 8 MiB 分散写 4 页、N=64 为主场景，以交错版本顺序独立重跑至少 10 个配对批次；以批次为重采样单位计算摊销耗时差的 95% bootstrap 区间，区间全部低于零才报告该场景加速。全写、小堆、N=1 与峰值恶化单列，即使未加速仍发布原始样本。
5. QEMU 可行性复跑已完成，基线为干净的 4d8fdf5。11 场景每项 36 次计时和 36 次计数，失败 0。8 MiB 只读整轮中位数 1.2743 ms，创建扫描 4096 槽，销毁逐页撤映射 2048 次。两种所有权策略尚无内核计时。进入原型的依据是可复现的剩余操作量，以及模型中已验证的隔离与释放规则。[QEMU 原始样本](batched.json) · [计时串口](batched-time-serial.log) · [计数串口](batched-counts-serial.log)

## 复跑

在本目录用 Python 3.10+ 执行模型，标准输出与归档 JSON 按 JSON 值比较。断言应启用。QEMU 基线在 Ubuntu 的 Seele 仓库用下列命令执行。

~~~sh
python3 model.py
cd ~/Work/Seele
python3 tools/bench_lifecycle.py --suite warm --runs 12 --batches 3 --variant batch-unmap --output build/ownership-validation/batched.json
~~~
