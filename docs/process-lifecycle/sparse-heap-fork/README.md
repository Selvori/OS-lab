# 普通 fork 的稀疏堆克隆研究

在 QEMU 上，64 KiB 只读负载从 fork 到 wait 的中位数由 **137.20 µs 降到 99.55 µs（−27.4%）**，子页表构建阶段的堆槽探查由 **4096 降到 16**。1 MiB 只读整轮中位数下降 22.1%。8 MiB 下仍需逐页建表和增加帧引用，五个场景的 fork 中位数上浮 0.8%–1.6%。

## 实现

`user_heap_clone` 先为子进程复制按地址排序的空闲区间链表。普通路径依次克隆各个空闲区间之前的已映射段及堆尾已映射段，子 PTE 安装成功后才增加物理帧引用。对有 \(F\) 个空闲区间、\(M\) 个映射页的堆，堆槽探查次数是 \(M\)，新增的区间遍历与 \(F\) 成正比。空堆无需探查堆槽。无空闲区间时遍历整个已映射堆。

`proc_fork` 在子地址空间构建成功后才写保护父页、刷新本地 TLB 并发布子进程。失败时 `proc_destroy` 按实际子 PTE 释放已安装映射、页表和链表节点。用户进程及其地址空间由启动 hart 独占，执行这些步骤时本地中断关闭。创建冻结映像复用该克隆路径，从现有冻结映像派生仍进入 `branch_attach`。

64 KiB 只读的整轮批次中位数依次为 134.25/142.90/136.90 µs 和 99.90/99.05/99.55 µs。整轮 P10–P90 为 132.25–159.80 µs 和 96.85–129.75 µs。计数版本的整轮 PTE 探查由 12446 降到 3793。

8 MiB 只读的 fork P10–P90 为 538.40–613.70 µs 和 545.65–598.00 µs。8 MiB 全写的整轮 P10–P90 为 43.925–161.824 ms 和 43.672–166.765 ms。分布重叠，当前单次按版本顺序运行的结果不足以判断 8 MiB 的小幅耗时变化能否复现。分散写四页的基准在一个**连续映射**的 8 MiB 堆上跨页表选取四个写目标，真正的稀疏映射由功能专项覆盖。接近全映射时可跳过的槽更少，额外链表遍历的开销取决于碎片数量。本轮未测满堆或高碎片堆的性能。

- 正式计时与计数样本各 792 个，共 1584 个，均通过 lifebench 页首/页尾内容校验与资源检查。每轮回收后用户页、内核页、区间节点、PCB 和文件对象余额均恢复至该工作集就绪时的值。释放预热堆后检查程序运行前的余额。
