## 逐个物理帧检查回池

同一个 2160 字节来宾程序只使用常规系统调用。它在关键状态等待串口输入，宿主暂停 QEMU，使用 ELF 调试符号解读该时刻的物理内存。宿主从创建者的 Sv39 页表取出所有原始物理帧地址，再逐页检查两条分支的实际映射、分配器引用计数和用户区空闲链表成员。每次快照同时核对整条空闲链表的长度与页池计数。下表仅统计最初那批原帧。[来宾源码](guest.c) · [宿主检查器](physical.py)

| --- | ---: | ---: |
| 历史基线 `df799fb`，同步整窗 | 0 | 2048 |
| 新内核，`freeze(2)` 同步整窗 | 0 | 2048 |

保留的原帧在每个窗口各有两个，分别映射到两条分支。挂接时每个原帧有 2 份物理引用，属于创建者和模板。创建者撤映射、两条分支放弃其余页后，逐页版的 2038 个原帧引用均为 0，且全部位于空闲链表。其余 10 个原帧各有 1 份引用，分支逐页读回初始内容。各组使用相同的来宾二进制与 Shell。[逐页快照](signed-p6-pin/physical-frames.json) · [同步整窗快照](signed-p2-pin/physical-frames.json) · [历史基线](baseline-five-windows/physical-frames.json)

另一个单页用例让创建者一直保留原映射。原帧的引用按“创建 → 挂接两分支 → 两分支均撤映射且作业已处理 → 创建者撤映射”的顺序为 **1 → 2 → 1 → 0**。前 3 个状态里原帧均在空闲链表外，创建者成功读回内容。第 4 个状态下该帧进入空闲链表，两条分支此时仍存活。[独立引用快照](signed-p6-owner/physical-frames.json)

## 从原始样本复算

独立脚本读取两份压缩 JSON，核对提交、来宾哈希、机型和 12 次启动编号。每次开机的四种关闭策略分别在繁忙和空闲场景记录 2048 个不同原帧。96 组的物理事件时序成立，所有异步批次均满足最多 **32 个确认步骤、8 份原帧减引用、1 次最终析构**。48 组繁忙场景的旁路进展记录覆盖从开始关闭到队列静止的完整区间。[复算程序](measurements.py) · [逐对结果与时延](paired.json)

| 8 MiB 分散写四页、顺序复用 64 次 | 每任务派生中位数 | 含排空的每任务摊销中位数 |
| --- | ---: | ---: |
| 原逐帧持有 `freeze(0)` | 124.24 µs | 910.84 µs |
| 32 帧分批持有 `freeze(3)` | 44.18 µs | 286.49 µs |
| 统一持有 `freeze(1)` | 30.83 µs | 181.37 µs |
| 有界逐页回收 `freeze(6)` | 31.70 µs | 308.31 µs |

复用 64 次的两条统一持有路径均有 0 次借用帧增引用。逐帧的两个对照均增加 130880 份引用，增引用的加锁次数由 130880 降至 4096。在已压低锁开销的对照下，统一持有仍降低了派生成本。

逐页版相对 `freeze(1)`，含排空的配对退化中位数为 **+72.26%**，预设方法的 95% 重采样区间为 **[+61.92%, +75.29%]**。单看派生和关闭前生命周期，配对中位数分别为 +5.14% 和 +6.97%，两个区间均跨过 +5%。逐页版关闭返回后等待全部完成的中位数为 7.78 ms，包含来宾主动让出和轮询的成本。本次逐帧快照用于正确性，时间取自独立性能运行。
