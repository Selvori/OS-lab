# 模板关闭后的有界逐页回收

8 MiB 原堆由两个长寿分支共同借用，每个分支在五个窗口各保留一页。逐页方案在两条分支仍存活时归还 **2038 个原物理帧**，三种整窗方案在同一检查点均归还 **0 帧**。逐页方案达到每调度机会全队列 **32 次确认、8 次减引用、1 次最终析构**的预算。8 MiB 分散写四页、复用 64 次时，含最终排空的摊销比已有统一持有策略高 **72.26%**，95% 配对区间为 **[+61.92%, +75.29%]**。该方案保留为显式研究策略，完整生命周期的 5% 门槛未通过。

## 策略和实现

| `freeze` 参数 | 所有权与关闭路径 |
|---|---|
| 0 | 原逐帧持有，私有表按帧增减引用 |
| 1 | 模板统一持有，模板对象析构时释放原堆帧 |
| 2 | 模板统一持有，同步确认、同步整窗释放 |
| 3 | 逐帧持有，私有表每批最多 32 帧增减引用 |
| 4 | 同步确认整窗，调度点分批释放 |
| 5 | 调度点增量确认，整窗就绪后分批释放 |
| 6 | 调度点增量确认，逐页放行并分批释放 |
| 7 | 检查构建的只记录模式，分支存活时保留原 PTE，按需用独立页表遍历核验 |

冻结时用克隆已经遍历的有效堆区间建立 64 槽掩码，申请作业页后才提交父映射的 COW 权限。每条分支在原 4 KiB 元数据页中增加 576 B 的单调解除位图。COW、代写或撤映射先提交 PTE 并完成本 hart 的 `sfence.vma`，再置解除位。当前私有帧由独立的 `owned` 位图负责。同址重映射延续既有解除状态，准备失败及回滚保留旧状态。

关闭摘除派生句柄并取得独立作业引用。进程槽按编号重新读取并核对模板身份，每次检查含无关和空槽均计入预算。跨批保存字、进程槽游标和部分交集，已经采样的字若遇到借用变更或分支离开，会加入复查。僵尸保留旧地址空间，至 `wait` 摘链后才离开确认集合。整窗确认与逐页确认复用掩码和游标，放行单位不同。

启动 hart 在内核根下关中断推进确认、释放和析构三个队列。预算按一次真实调度机会合计，确认与释放作业按步轮转。释放批先清模板叶子并刷新本地翻译，再调用页池减引用。共享末级表的存储留到最后一条分支链接摘除。所有剩余槽仅被借用而无可推进工作时，队列休眠，借用变更会重新入队。无分支关闭仍经预算处理，最终析构单列。增量候选比 `freeze(1)` 多一页模板作业元数据，分支元数据页数相同。参见 [回收源码](../../../kernel/mm/template.c)、[调度和模板生命周期](../../../kernel/proc/proc.c)及[页池](../../../kernel/mm/page.c)。

## 正确性与总预算

| 用例 | 实测结果 |
|---|---|
| 创建者独立持有 | 关注同一 PA。两分支解除后模板减引用一次、回池零页。创建者仍读到初始值，页池引用数为 1。随后创建者撤映射，同一 PA 首次发布到空闲链表。 |
| 五窗十页 | 堆从 `0x3000` 起，五窗分别有 509／512／512／512／3 个原页。`freeze(6)` 的 2038 个非钉住页逐一命中减引用与回池事件，十个钉住页逐一无事件且读回成功。模式 2、4、5 在同一检查点逐帧验证为 0。逐页模式的活体额外用户页为 4099，整窗模式为 6137，均含来宾固定页。释放最后十页后资源余额恢复。 |
| 单分支全覆盖 | 四种关闭策略写满 2048 页后检查全部 2048 个不同 PA 的回池时间，分支保持存活。写回验证与最终资源余额均通过。 |
| 独立页表核对 | 只记录模式逐槽使用原 PTE 的 PA 对比各分支实际有效叶子，同时核对分支解除位与拟释放集合。有共享末级表及已拆表分支。稀疏用例可释放计数依次为 0、1、1、2。 |
| 跨批变更与槽复用 | 五窗活体专项在逐页策略观察到 129 次已经采样的同字再变更。稀疏专项让僵尸仍钉住最后一页，`wait` 后普通子进程复用同一槽，页表审计随后通过。 |
| 分配失败 | 策略 3、6、7 覆盖冻结 8／9／9 个分配点、派生 8 个、跨窗拆表 2 个、mmap 3 个、exec 3 个、跨页代写 4 个（含后半帧分配失败）。逐轮检查余额，失败后的映射仍可读，随后的成功代写和 exec 或 wait 正常。 |
| 并发作业及回收 | 创建者隐式关闭时仍有一个僵尸借用者，收养并 reap 后作业归还 100 份模板引用，独立 PA 记录确认 100 帧最终回池。两个零分支作业并存时，积压 4096 份引用，释放全数引用并析构两对象，创建者持有期间回池为 0。该轮执行 1 个繁忙批次和 512 个空闲批次，最大全队列工作量是 32／8。 |
| 钉住时空转 | 单独等待 3 个 100 Hz tick，候选的活跃批次数保持 260 → 260。关闭后重复 close 或 spawn 返回 `-22`。 |

## 开放期派生

QEMU 5.1.0，双 hart，128 MiB，Ubuntu GCC 11.4。计数与计时各自构建，Shell、开放期和关闭期三个来宾二进制的 SHA-256 一致。计时使用 12 次独立开机，策略顺序 0／3／1／6 与其逆序各六次。每次开机先各预热两轮。表中为 8 MiB 分散写四页、复用 64 次的中位数，单位 µs。每次派生同步 `wait` 后再派生下一次。排空时间从关闭调用返回到来宾观测作业结束，含让出、轮转和轮询。

| 策略 | 冻结 | 每次 spawn | 关闭调用 | 关闭后排空 | 含排空的每任务摊销 |
|---|---:|---:|---:|---:|---:|
| 0 逐帧单独加锁 | 124.30 | 124.24 | 222.00 | 24.80 | 910.84 |
| 3 逐帧分批加锁 | 118.70 | 44.18 | 215.45 | 21.90 | 286.49 |
| 1 统一持有 | 117.20 | 30.83 | 211.15 | 21.45 | 181.37 |
| 6 有界逐页 | 118.85 | 31.70 | 21.20 | 7783.30 | 308.31 |

一组计数样本中，策略 0 和 3 都为借用安装 130880 份引用，获取页池锁分别 130880 和 4096 次。两版私有表退出各减 130880 份引用，含末次引用回池发布的锁获取分别为 131136 和 4352 次。这个减引用口径取自回滚和末级表遍历，单页 COW 或显式撤映射的独立释放走原路径。策略 1 和 6 借用帧增引用均为 **0**。四种策略复制的末级槽数均为 130880。策略 6 在关闭后另减模板的 2048 份原帧引用，创建者在该检查点仍持有全部页，实际回池 0 页。

相对差以同次开机的候选除以对照后减 1，每项做 20000 次成对重采样并给出百分位 95% 区间。策略 1 相对策略 3 的每任务摊销下降 **36.49%**，95% 区间 **[−40.08%, −32.52%]**。策略 6 相对策略 1 的 spawn 相对差中位数 **+5.14%**，区间 **[−4.21%, +11.05%]**。关闭前每任务为 **+6.97%**，区间 **[−1.06%, +8.57%]**。这两个口径尚不能确认满足 +5% 门槛。

复用 1 次、8 次及集中写四页复用 64 次也各有 12 对。含排空的每任务摊销分别为 8385.55／1274.98／298.62 µs，对应策略 1 为 596.50／228.36／174.23 µs。逐对及各指标区间见[开放逐对样本](open-pairs.csv)、[独立计数](open-counts.csv)和[完整汇总](summary.json)。

## 关闭期、驻留和调度延迟

8 MiB 单分支写满后存活，创建者先撤原映射。独立旁路进程每轮完成固定 128 次整数运算再让出，首条进展早于关闭，末条在队列静止之后。48 个旁路组均通过边界及缓冲容量检查。每策略采集 12 个繁忙样本和 12 个空闲样本，按开机轮转策略顺序，交替繁忙／空闲先后。

| 繁忙策略 | 关闭调用 P50 µs | 前四窗末次写 P50 µs（逐窗） | 回池距最后借用解除 P50 ms | 每轮旁路最长间隔的中位／最大 ms | 用户页峰值（计数） |
|---|---:|---|---:|---:|---:|
| 2 同步整窗 | 80.70 | 606.25／515.35／525.70／539.85 | 0.005 | 10.212／10.779 | 2580 |
| 4 仅分批释放 | 28.50 | 22.95／13.45／13.05／13.35 | 7.093 | 10.147／10.218 | 4068 |
| 5 增量确认整窗 | 15.80 | 12.40／12.60／12.45／12.45 | 6.715 | 10.157／10.347 | 4100 |
| 6 增量确认逐页 | 16.45 | 12.90／12.80／12.85／13.30 | 6.972 | 10.102／10.775 | 4044 |

同步和逐页两个繁忙组的第五窗末写中位为 27.05／12.60 µs，全部 2048 次写的 P99 为 40.03／34.40 µs，观测最大为 1198.7／320.1 µs。各窗口及每轮最慢五次写保存在 [关闭逐轮数据](close-samples.csv)。策略 6 的关闭调用观测最大值为 1305.3 µs，高于同步组的 145.9 µs。策略 6 繁忙时逐帧从最后一次借用解除到回池的 P50／P95／P99／最大值为 19.04／32.90／37.43／39.39 ms。同步整窗为 4.02／8.00／9.53／11.14 ms。分批压低大窗末写，同时推迟实际回池并提高全覆盖的峰值驻留。旁路最长间隔仍约 10 ms，与 100 Hz 抢占节奏接近。

策略 6 繁忙批次时长 P50／P95／P99／最大值为 9.9／16.8／32.5／75.0 µs，空闲批次所在组为 9.6／15.2／27.2／274.9 µs。从最后一次借用解除到最后一个原帧回池，空闲组的逐页中位数为 3.584 ms，最大 4.335 ms。最终析构在繁忙组中位为 25.15 µs，计数样本释放 9 张页表、合计 12 个内核页和 1 个固定用户页，原堆帧已在批次中处理。同步方案释放同样 9 张表、合计 11 个内核页。用户页峰值以用例初始余额为基准，含旁路采样页；队列静止时子进程仍持有私有内容，繁忙组各策略均为 2069 个额外用户页。

一次写用两条 `rdtime` 包夹，10 MHz 来宾时钟每 tick 为 0.1 µs。原帧时间分别取借用撤销且刷新之后、模板交给减引用 API 之前、分配器发布到空闲链表之后。回池时间包含填充和发布成本。批次时间包含批内取队列、确认、清 PTE、刷新、填充、发布和该批发生的固定析构。计时包含采样指令及时间戳记录，没有扣除测量开销。计时单位为 QEMU 客体观察时间，操作数有硬上限，时间分布为本次环境的观察值。实机范围为 ELF/FIT 构建。

## 复验

在 Ubuntu `~/Work/Seele` 检出 `research/template-bounded-reclaim`。原始时间与计数均来自干净的 `d8432a6aa823b0273938d56741fa64f08eb31a87`。后续 `40186f7` 扩展逐页检查的证据输出并加入统计脚本，计时内核与来宾不变。使用新的输出目录可避免覆盖证据。

~~~sh
cd ~/Work/Seele
python3 tools/bench_bounded_reclaim.py build/bounded-accept check --checks bcheck
python3 tools/bench_bounded_reclaim.py build/bounded-accept-full check counts time
python3 tools/report_bounded_reclaim.py build/bounded-accept-full build/bounded-accept-full/summary
python3 tools/report_bounded_reclaim.py docs/process-lifecycle/template-bounded-reclaim/raw build/bounded-recompute
python3 tools/test_lifecycle.py --output build/bounded-accept-regression
python3 tools/bench_template.py build/bounded-old-template check --smoke
python3 tools/bench_window_reclaim.py build/bounded-old-window check
make CONFIG=riscv64-qemu-virt-sbi build
make CONFIG=riscv64-qemu-virt-sbi run
make CONFIG=riscv64-visionfive2-uboot build image
dumpimage -l build/riscv64-visionfive2-uboot/kernel.itb
~~~

旧模板与窗口专项通过，生命周期 8 轮及 Lab 5／6／9 扩展回归通过，旧回归脚本按哈希恢复临时源码。正式 QEMU 双 hart 启动，`pwd` 输出 `/`，退出状态为 0，ELF 入口 `0x80200000`，正式 ELF 无生命周期、帧跟踪或审计探针符号。VisionFive 2 ELF 和 FIT 入口均为 `0x40200000`，`dumpimage` 校验 49232 字节内核载荷。首次强制重制 Shell 镜像遇到已有目标，改用新镜像路径复验并保留原盘。开发试跑还修正了旁路结束采样及孤儿用例的回池归属，原始记录随包保存。
