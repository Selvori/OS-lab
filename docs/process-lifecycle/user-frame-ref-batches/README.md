# 普通 COW 堆帧引用分批更新

8 MiB 只读普通 fork 到 wait 的中位耗时由 **0.90505 降至 0.44330 ms（−51.0%）**，基线复测为 0.92510 ms。fork 相位由 0.32245 降至 0.08865 ms（−72.5%），wait 销毁由 0.41250 降至 0.18830 ms（−54.4%）。三个批次均改善，达到 20% 的研究阈值，保留该实现作为独立研究分支。

## 实现

- `user_vm_clone_heap_span` 沿既有的 Sv39 末级表边界遍历映射，每批先验证待复制叶子，再在用户页池锁内取得最多 32 个引用，随后才安装有效子 PTE。失败回滚只遍历已安装的子叶，父表继续在整个子地址空间构造成功后提交 COW 权限。
- `user_vm_clear_heap` 先撤销该末级表范围的映射，再执行本核 `sfence.vma`，然后收集帧号并执行分批减引用。每批归零的帧由末次释放者独占，锁外完整填充 `0xa5` 并串成链，持锁拼接到空闲链表和更新计数。尾批在当前段末处理。
- 批处理仍使用原有按帧引用表和用户页池锁。适用路径是私有堆克隆及 wait、exec 和构造失败中的整体清理。普通进程的页表由单一 owner hart 操作。

## 验证与复跑

- 原有 `test_lifecycle.py --guest-only` 八轮通过，覆盖父子隔离、稀疏跨表、部分建表失败和资源回滚。
- 35 页专项八轮通过。注入后续末级表分配失败，核对克隆先前已保留的 34 个引用全部交还、父映射权限和物理帧保持原状、资源余额恢复。成功分支把 33 页连续段的第 2 页和第 33 页写成私有页，wait 会遇到 31 个共享引用与 1 个末引用混合的完整批，以及含 1 个末引用的尾批。父内容、引用数和余额均恢复。
