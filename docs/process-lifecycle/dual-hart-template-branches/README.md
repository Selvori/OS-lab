# 模板派生进程的双 hart 用户态执行

从已推送的 research/dual-hart-users / 9e3a6535bef19eb7aee68122a49f9b9b6bbeed7a 建立 research/dual-hart-template-branches。实现提交为 d757d2225805c7a4b720f08a005f9f29a40e6e69，签署采集提交为 14a92b3998adc00a05cc215edcf8fc5c844204e5。构建 QEMU virt 时启用 DUAL_HART_USERS=1，freeze(1) 和 freeze(9) 的实际派生进程可在两个 hart 并行执行用户代码。关闭句柄后仍可派发已有分支。启动 hart 持续独占进程状态、所有系统调用、COW、撤映射及资源销毁。其他模板策略沿用本地派发，普通进程沿用既有 16 次系统调用阈值。

## 旧翻译与模板生命期

- spawn 完成子根、陷阱现场及模板引用的准备后发布一个可直接进入 U 态的上下文。启动 hart 仍须选出一个本地可运行进程才会派发竞争者。远端借用的是实际分支的用户根及陷阱页。模板 PCB 始终处于 PROC_USED，模板根不参与调度。
- 远端通过 trampoline 切回内核根，执行本地 sfence.vma，再通过常驻栈发布 WORKER_DONE。启动 hart acquire 收取现场，再把 PROC_REMOTE 改为可运行。同步异常和系统调用通过原进程内核栈重放。COW 或 munmap 先改变分支翻译并再做本地 fence，然后才登记 dropped 位。exec 或 wait 先撤分支目录链接并 fence，再减少模板引用。远端的持有状态阻止旧根、旧表或陷阱页同时被撤销。
- 两种策略都让模板承担借用堆帧的引用，派生只有一份模板引用。固定代码、数据和栈沿用独立帧引用和 COW，首个混合窗口的末级表由分支私有、其中原堆帧仍借自模板。后续纯堆窗口可共享末级表，用户只能读取共享的 COW 叶。有效页的 A 位在发布前已设置，可写私有叶的 D 位按原规则设置。修改共享窗口中的一个借用槽前先将整个窗口拆为分支私有表。
- 策略 1 持有原堆帧直到最后一个分支解除模板引用。策略 9 关闭先移除唯一派生句柄。关闭时仍有分支的作业用 held 与所有关联分支的 dropped 求交，PROC_REMOTE 和僵尸仍参与。某一原页能进入释放集合时，每条分支要么已在切回内核并 fence 后撤销该借用，要么已完成整支拆除。仍链接共享末级表的分支不会对该表的原槽登记 dropped。保有借用的私有混合首表同样阻止原页释放。解除位单调增长，关闭后不会出现新派生借用。其他进程即使仍有同一原帧的独立引用，也有自己的 PTE 和引用计数。
- 策略 9 的零分支捷径只在关闭瞬间已无分支时启用。作业引用保护模板目录和末级表，直到全部减引用且分支数为零再析构。只有远端用户代码活跃时，启动 hart 在空扫描末尾可以做一次有界忙批，然后等待中断。在队列中的其他模板沿用既有轮转，每次调度机会合计最多 32 步确认、8 次原帧减引用、1 次析构。

## 四组交替开机计时

Ubuntu 22.04.5，QEMU 5.1.0 virt，OpenSBI 0.7，128 MiB，-smp 2，-accel tcg,thread=multi，来宾时钟 10 MHz。两侧都以 DUAL_HART_USERS=1、LIFECYCLE=time 构建，直接使用各自已构建的 ELF 启动 QEMU。每次开机前后核对 ELF 摘要，所有开机使用同一份且摘要未变的磁盘。一次试跑曾被 make run 从候选源码重编基线，已排除。正式基线 c156fd8b… 另与从 9e3a653 全新归档源码重建的可装载二进制逐字节比对。

每次开机按预定顺序预热两策略各一轮，再各测一轮。每轮创建者从已初始化的 8 MiB 快照连续 spawn 两条兄弟分支，在两支尚活时关闭句柄。每条分支执行 1.28 亿次整数递推，两次扫描 2048 页校验数据，在混合首窗和纯堆窗各私写一页，并撤掉一个私写页和一个仍借用的页。两者退出值以各 PID 独立复算，父进程的所有原页内容及两页池、进程槽和其他资源余额均检查通过。下表是来宾阶段时间，开始点在第一次 spawn 前，完成点为第二次 wait 返回。

| 指标 | 策略 1，基线 → 并行 | 策略 9，基线 → 并行 |
| --- | ---: | ---: |
| 第一次 spawn 中位数（µs） | 67.50 → 66.60 | 66.30 → 66.10 |
| 第二次 spawn 中位数（µs） | 61.95 → 62.25 | 62.05 → 80.35 |
| 两分支完成中位数（ms） | 329.09 → 166.56 | 325.02 → 166.15 |
| 四对加速比的中位数 | 1.97× | 1.96× |
| 关闭调用中位数（µs） | 41.25 → 41.50 | 43.20 → 42.50 |
| 两支 wait 后到排空（ms） | 0.094 → 0.100 | 20.07 → 19.66 |
| 关闭返回到排空（ms） | 328.97 → 166.50 | 344.93 → 185.42 |

策略 1 的模板在最后一次 wait 返回前已销毁，测得的末段是来宾探测开销。策略 9 在最后一次 wait 后八个样本的队列状态均为 3，即一个待完成作业且还有可推进工作。排空终点是作业与固定析构都已结束。配对计时保留创建者的全部原帧映射，策略 9 独立计数核对了 2048 次模板减引用、0 帧此时回池。真实回池另见五窗专项。每策略仅四对独立开机，派生与关闭的细小变化按描述性样本解读。 [逐次计时与配对原始值](time/paired.json) · [构建与磁盘摘要](time/artifacts.json)

### 单分支串行对照

每次开机另执行既有 bopen，顺序 spawn/wait 16 次，8 MiB 模板上每次分散私写四页。策略 1 的派生中位数为 59.74 → 61.13 µs/次，含冻结、关闭及排空为 450.13 → 475.03 µs/次，配对变化中位数 +4.86%。策略 9 的派生为 64.66 → 62.06 µs/次，完整摊销为 687.73 → 677.97 µs/次，配对变化中位数 +1.24%。策略 9 的关闭调用为 66.45 → 63.60 µs，随后零分支排空为 3.369 → 3.434 ms/批。单分支负载没有两条兄弟计算的并行机会。

## 双 U 态与远端写缺页见证

独立定格试验中，关闭后的策略 1 与策略 9 均在同一暂停里观察到两个 hart 的 priv=0，PC 落在同一来宾计算函数，satp 分别对应同一父进程的两个真实 spawn 子进程。策略 9 的例子是 hart 0 的 satp 0x8000000000080348 和 hart 1 的 0x8000000000080350，相关模板根是 0x8033d000。对照只看到一条分支处于 U 态。正式计时覆盖由 hart 0 和 hart 1 启动的开机。 [GDB 见证与 PCB 对应](witness/witness.json) · [策略 9 原始寄存器](witness/witness-parallel-9-gdb.txt.gz)

另一独立 GDB 运行由 hart 1 启动。远端 hart 0 在写缺页后已经切回内核 satp。启动 hart 1 随后用同一陷阱页重放 scause=15、地址 0x6000。模板已关闭，该页在进入 branch_drop_borrow 时解除位仍为 0，函数返回时为 1。来宾继续通过数据校验、回池与余额检查。 [交回现场](checks/remote-cow-gdb.txt.gz) · [结构化检查](checks/checks.json)

## 五窗原帧、调度上限与回归

- 策略 9 的专门测试让两个 8 MiB 模板兄弟在各五窗保留不同的一页。创建者撤映射并关闭后，活分支阶段实际回池 2038 帧。在同一个 GDB 暂停点，两条分支仍同处 U 态，模板 held 恰剩 10 帧，位图与两支各自未解除的五页逐位吻合。该快照中两支的五个窗口均已私有化，原帧仍按模板借用。最后 2048 帧均实际回池，逐帧记录有减引用和回池事件。两轮都逐批检查 32 步确认、8 次减引用和 1 次析构上限，实际各析构一次。 [双 U 态五窗串口](checks/witness-parallel-9-pin-serial.log.gz) · [五窗位图原始读数](checks/witness-parallel-9-pin-gdb.txt.gz)
- 两策略的双分支检查均为零借用堆帧增引用。既有 bcheck 9 同样通过五窗 2038/2048 回池，零分支保留创建者与稀疏撤映射检查分别核对了 2048 次减引用、0 回池和 2022 次减引用、2022 回池。另通过队列轮转、既有策略 6 部分失败回滚及八轮生命周期检查。GDB 的跨核结论来自独立见证。 [专项与回归串口](checks/checks-serial.log.gz)
- 开关两态的正式 QEMU build/run 通过，Shell 回显正常，入口均为 0x80200000。VisionFive 2 的 ELF 与 FIT 构建、dumpimage 通过，入口为 0x40200000。动态结果来自 QEMU。 [QEMU 入口](build/official-entries.txt) · [FIT 信息](build/visionfive2-fit.txt)

## 复跑

在 Ubuntu 的 Seele 仓库检出 14a92b3 或此报告提交。基线用原提交的归档源码构建。归档路径变化会改变 ELF 的调试信息摘要，正式基线与这种构建的可装载二进制一致。

~~~sh
root="$PWD/build/dual-hart-template-replay"
mkdir -p "$root/source"
git archive 9e3a6535bef19eb7aee68122a49f9b9b6bbeed7a | tar -x -C "$root/source"
make -C "$root/source" CONFIG=riscv64-qemu-virt-sbi DUAL_HART_USERS=1 \
  LIFECYCLE=time BUILD="$root/base" build
for mode in time witness check; do
  python3 tools/bench_template_dual_hart.py "$root/$mode" "$root/base/kernel.elf" "$mode"
done
(cd docs/process-lifecycle/dual-hart-template-branches && sha256sum -c SHA256SUMS)
~~~
