# RV64 对齐整页填充与复制

2026-11-19 进程生命周期优化第二轮。8 MiB 堆写遍全部 2048 页时，从 fork 到 wait 的中位耗时由 **45.850 降至 29.098 ms，下降 36.5%**。候选之后复测原版为 46.287 ms，对应下降 37.1%。主指标达到计划设定的 20% 门槛。

## 实现与范围

[内存例程](../../../kernel/lib/string.c)对 4096 字节、页对齐的内核操作按 64 位字处理 512 个位置。填充将参数截断为一个字节，再复制到 64 位字的各字节。复制要求两个地址都按页对齐。GNU C 的 `__may_alias__` 允许通过该字类型读写任意类型的对象表示。短块、带尾长的操作和任一地址未对齐的操作走原有逐字节逻辑。[内核构建规则](../../../mk/build.mk)只为内核 `string.o` 启用快路径，用户程序继续使用原字节例程。

`page_alloc()` 在交付页前完整清零。`page_free()` 最后一次归还引用时完整填充 `0xa5`，再将页加入空闲链表，页首链接字段由分配器使用。COW 分离先分配清零、再复制整页、最后发布新页映射。页池锁与 COW 同步沿用原实现。反汇编显示原版循环为 `sb` 和 `lbu/sb`，新版整页循环为 `sd` 和 `ld/sd`。[反汇编](evidence/candidate-memcpy.txt) · [原版反汇编](evidence/baseline-memcpy.txt)

## 同输入对照

按基线 → 候选 → 基线复测的顺序运行三套 warm 基准。QEMU 5.1.0 virt、128 MiB、两个 hart、10 MHz time，用户进程由启动核调度。计时版与计数版分别启动。每套每种模式为 11 场景，每场景预热 2 次，再采 3 批 × 12 次。共 1188 个正式计时样本和 1188 个正式计数样本，每个预热批次及采样批次都返回 `LIFE PASS`。

基线 `6fa4fd5` 是第一轮实现 `8e59fad` 的报告提交，实测 ELF 与第一轮 `optimized.json` 哈希相同。最终候选为 `44802a0`。试采曾让共享源码中的字宽路径进入用户程序，产物哈希检查识别了该混杂因素。限定内核编译后重采候选及复测基线。正式数据的 `sh`、`lifebench`、`lifejob` 在每种构建模式跨三套均逐字节相同。[版本与哈希](verification.json)

## 局部影响与退化

8 MiB 全写中，`fork` 内核耗时从 0.561 降至 0.545 ms，`wait` 销毁从 5.915 降至 1.829 ms（−69.1%），父进程阻塞等待从 39.270 降至 26.413 ms（−32.7%）。父进程阻塞时间包含子进程运行和调度，单次缺页与单次搬运耗时需另行测量。8 MiB 立即 `exec` 的旧堆回收从 0.461 降至 0.397 ms。

所有场景的整轮中位数、三个批次整轮中位数和整轮 P90 均下降。按阶段汇总，唯一高于第一次基线的中位数是 8 MiB 只读的父进程阻塞等待，132.20 → 133.85 µs（+1.25%）。复测基线为 134.65 µs，候选比该值低 0.59%。阶段批次的六个上浮点全部列在 [验证记录](verification.json)。短块及非对齐路径多一次大小判断，编译器也重新安排了字节循环。短块吞吐仍待单独计量。

所有计数样本按场景逐项一致。8 MiB 全写包含 2048 次用户写缺页及 1 次内核代写分离，总复制 8,392,704 字节，额外用户页峰值 2049、额外内核页峰值 11。每轮恢复到预热父进程的余额，解除预热映射后恢复到批次前余额。8 MiB 只读仍需为 wait 代写分离 1 页，分散写场景共复制 5 页。[全部计数与余额](counts.csv)

## 验证与适用条件

临时来宾冒烟用逐字节参考校验 144 组复制与 180 组填充，覆盖零长、7／8／9 字节、页长 ±1、页对齐、8 字节但非页对齐、源或目标非对齐、`0xa5` 及整数截断。检查返回地址、源完整性和范围外哨兵。两个页池各执行分配、写满、释放、重新分配，确认全页归零及空闲计数恢复。`kernel/main.c` 已按 SHA-256 恢复，正式内核重建和 QEMU 双 hart 启动通过，磁盘 Shell 可正常执行 `echo`。QEMU ELF 入口为 `0x80200000`。VisionFive 2 ELF 与 FIT 构建通过，入口为 `0x40200000`。[验证与构建证据](evidence/entries.txt) · [冒烟串口](serial/smoke-serial.log.gz)

性能结论适用于本次 QEMU 与 warm 负载。三批共享各自模式的同一次开机，结果用于研究路线选择。板端性能及各搬运操作的独立收益仍待测量。
