# 预热父进程基准与比较

8 MiB 工作集只读任务的 fork 到 wait 中位耗时从 36.535 ms 降至 5.344 ms，额外用户页峰值从 2051 页降至 1 页。写遍工作集时，中位数由 36.497 ms 升至 46.382 ms。标准 COW 将复制成本转移到实际写入，子页表的建立和撤销仍随工作集增长。

## 软件、负载与计量

- 深拷贝内核来自 aaf1420fa70299af2d4b60db9b75b50955e92c29，COW 内核来自 14ec33c428bd1d5e26a19ac3440cd629676e5c26。两次在同一个 Ubuntu VM 的干净提交上全量编译；两版的 Shell、基准与 exec 目标二进制逐字节一致。记录了[用户程序 SHA-256](programs.sha256)、[深拷贝 ELF SHA-256](deep-elf.sha256)及 [COW ELF SHA-256](cow-elf.sha256)。
- QEMU 5.1.0 virt、OpenSBI v0.7、128 MiB、双 hart，由启动核调度用户进程。使用 riscv64-linux-gnu-gcc 11.4.0，内核 -O2、用户程序 -Os。计时为经平台定义核实的 10 MHz RISC-V time，每单位 100 ns。预热套件中两个 time 构建分别记录 528 个背靠背空读差值，中位数均为 0 tick，范围分别为 0–23 与 0–101 tick。表中以 0.001 ms 显示，精度受 QEMU 和宿主调度影响。
- 每个场景先跑一个 2 轮预热批次，再跑 3 个 12 轮批次。每批父进程只 mmap 并填充工作集一次，重复 fork 一个子进程，检查其退出结果，wait 后验证父进程每页首尾和资源余额。一轮只写所选页的首字节，并核验写后值；只读子进程检查每个映射页的首尾。exec 子进程真正加载磁盘 /bin/lifejob，校验参数后退出。UART 汇总在批次计时之后。
- 集中写选索引 0–3 的 4 页，命中一个末级页表。8 MiB 分散写用索引 0、512、1024、1536，地址在 0x3000 起按 2 MiB 递增，命中四个末级页表。8 MiB 全量写 2048 页，因 0x3000 起点偏移而横跨五个末级页表。64 KiB 和 1 MiB 全量写各命中一个末级页表。
- 时间取 time 构建的每轮中位数，整轮区间另给 P10/P90（36 个样本的最近秩）；每批初始化与 12 轮批次时间各取三批中位数。计数取独立 counts 构建中位数。PTE 探查涵盖 walk、销毁和剪枝实际访问；用户页峰值是当轮较开始额外占用。完整口径见[测量说明](README.md)。

- 堆只读仍有一次 COW 分离。wait 在回收前写入父用户栈上的退出状态，彼时僵尸还持有原栈页。少量写在同等 4 页下跨 1 张或 4 张末级页表，均复制 20,480 B、峰值 5 页，PTE 探查均为 449,334。两组整轮区间重叠，本次采样无法归因跨表选址的延迟差。
- 8 MiB 全量写的 COW 复制 8,392,704 B，接近深拷贝的 8,400,896 B，同时发生 2048 次用户写缺页和对应的本地 TLB 失效，加上 wait 代写。COW 整轮 P90 达 164.069 ms。保留包含长尾的样本，现有采样无法定位 QEMU/宿主调度波动的来源。64 KiB 全量写的中位优势缩至 0.088 ms，此时每轮仍付出 16 次写缺页。
- 8 MiB fork/exec/wait 中位数 36.732 → 5.727 ms。COW 只复制子进程写参数时的栈帧，并在三张新用户帧上准备 exec；父 `wait` 时原栈已独占，可以原地升级。深拷贝在 fork 复制 8,400,896 B，exec 从暂存页到映像另搬运 8,192 B；COW exec 直接在新帧准备，省去这次搬运。两版均从磁盘读取程序，读取所需搬运由文件系统承担，未计作 COW 复制。
- 两版普通 fork 均探查 4096 个克隆堆槽和 4096 个销毁槽。exec 与最终 wait 各一个堆销毁区间，合为 8192 槽。8 MiB 时两版均分配并回收 9 个子表节点。COW fork 另外遍历实际映射的用户页以提交父表权限。8 MiB 只读 COW 的整轮 5.344 ms 中，创建中位数 0.522 ms，wait 中回收 4.643 ms。源码中撤销每页后重新检查同一张末级表是否为空；密集区间使这些表项检查快速增加。从 1 MiB 到 8 MiB，COW 只读探查由 24,103 增至 449,322。
- 所有测量均验证每轮和整批解除映射后回到对应版本的起始资源余额。以 8 MiB 普通任务为例，轮末深拷贝与 COW 用户/内核空闲页分别为 22121/7939 和 22108/7935，两边堆节点、活跃 PCB、动态打开对象分别为 126、2、0。两版的绝对页池起点受内核镜像大小影响，COW 含 64 KiB 静态引用计数表，峰值比较使用各自的相对起点。

下一阶段应先验证同一末级表的批量撤映射及一次性空表检查，比较每轮 PTE 探查和销毁时间。若再试共享页表，需单独测量父子 PTE 变更的隔离成本，并继续用深拷贝和本分支标准 COW 作为对照。

## 重现命令和原始记录

在 Ubuntu ~/Work/Seele 工作区干净时运行。两次使用同样的基准程序与参数。比较脚本从原始样本重新计算中位数、P10 和 P90，并核验逐轮资源余额与分配/归还配对。

~~~sh
git switch --detach aaf1420
python3 tools/bench_lifecycle.py --suite warm --output build/process-lifecycle/deep-warm.json
git switch --detach 14ec33c
python3 tools/bench_lifecycle.py --suite warm --output build/process-lifecycle/cow-warm.json
python3 tools/compare_lifecycle.py build/process-lifecycle/deep-warm.json build/process-lifecycle/cow-warm.json
python3 tools/test_lifecycle.py
~~~
