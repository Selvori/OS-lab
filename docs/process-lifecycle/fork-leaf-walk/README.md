# 普通 fork 复用 Sv39 末级页表

2026-11-19，进程生命周期优化方向 F。QEMU 的 **8 MiB 只读 fork 至 wait 中位耗时从 1.15330 降至 0.90380 ms（−21.6%）**，fork 内核相位从 **549.60 降至 321.65 µs（−41.5%）**。三个采样批次的两个指标均下降，主指标达到本阶段的 20% 探索门槛。

## 做法

堆空闲链表的补集仍界定有映射的区间。[克隆与提交](../../../kernel/mm/heap.c)将每个区间交给 [用户页表代码](../../../kernel/mm/user.c)，后者在 2 MiB 末级表边界切段。子表构建每段定位父、子各一次，顺序检查父有效叶、物理地址范围和子槽占用，安装带 `V/A/R/U/COW` 的只读叶，然后逐帧增加引用。首次父槽到最后父槽均执行原有权限检查。父表仍在完整子表构建之后清除 `W` 并设置 `COW`，[调用者](../../../kernel/proc/proc.c)执行本地 `sfence.vma` 后发布子进程。非堆的固定映像页沿用单页路径。

段边界计算和堆专用叶安装是新增代码，每个映射段仍有定位成本。子表先为该段定位或分配，再检查段内各源叶，错误由原有的未发布子树销毁路径回收。被复制的堆帧引用、页表页、进程资源和同步由原模块管理。模板冻结复用上述流程，已有模板的派生仍独立调用 `branch_attach`。单 owner、关中断、私有表的约束沿用原实现。

## 同输入对照

基线 `98848fe` 的代码与 `44802a0` 一致，候选 `ce1fe06`。依次在同一 Ubuntu VM 运行两版。QEMU 5.1.0 virt、128 MiB、双 hart、10 MHz time，GCC 11.4。时间和计数各独立启动。每版每种模式 11 个场景，每场景预热 2 次、正式 3 批 × 12 次。共 792 个正式计时样本和 792 个正式计数样本，零失败。两版两种模式的 `sh`、`lifebench`、`lifejob` 分别逐字节一致。

8 MiB 只读的整轮批中位数为 1131.90、1183.90、1159.35 → 894.50、906.00、908.80 µs。整轮 P10–P90 为 1110.80–2211.45 → 885.40–987.45 µs，fork 相位为 532.70–1118.85 → 314.05–349.45 µs。wait 销毁相位中位数为 425.60 → 412.70 µs，父进程阻塞等待为 135.25 → 130.25 µs。改动落在 fork，后两相位的变化反映本次采样。

8 MiB 的 2048 页跨 5 张末级表。基线的父查找、子建表定位和父权限提交各做 2048 次 walk，候选各做 5 次。少做一次 walk 省去两次上层探查。于是各 8 MiB 场景均少 `3 × 2 × (2048 − 5) = 12258` 次 PTE 探查。8 MiB 只读整轮下降 43.4%。每页三次末级槽检查均计入，`sv39_walk` 负责首槽计数，顺序循环补计后续槽。64 KiB 的 16 页同属一表，少 90 次探查。计数版 396 对正式样本的其他非时间字段逐项一致，包含克隆槽、COW 次数、复制字节、两页池、进程槽和文件对象余额。8 MiB 只读的额外用户／内核页峰值都是 1／11 页。

64 KiB 连写四页的整轮中位数上浮 1.8%，P90 为 131.70 → 212.70 µs，候选第三批整轮中位数明显偏高。8 MiB 全写的整轮 P10–P90 大量重叠，第三批整轮中位数上浮 2.2%。每种模式的三个批次来自同一次开机；独立开机波动、硬件耗时及高碎片堆的性能本轮未测。[全部计时与各批分位](timings.csv) · [全部计数与资源余额](counts.csv)

## 验证

`tools/test_lifecycle.py --guest-only` 八轮通过。稀疏布局覆盖 `0x1ff000` 至 `0x200000` 的边界和跨表空洞。刻意在子进程前两张末级表已有映射后令后续建表失败，检查父帧、引用、原可写权限和资源余额。成功 fork 后检查子写隔离和父页内容，回收后余额正确。模板既有来宾检查 `TC PASS` 与三种策略的 `PIN PASS` 也通过。[生命周期结果](verification.json) · [模板结果](template-check.json)

正式 QEMU 构建与 `make run` 双 hart 启动通过，ELF 入口为 `0x80200000`，Shell 的 `pwd` 返回 `/` 后由 Ctrl-A/X 正常退出。首次冒烟盘只装入了 Shell，调用外部 `echo` 返回找不到程序；改用内建 `pwd` 完成相同启动检查。验证使用独立探针构建目录，正式源码无需恢复。[串口记录](serial/formal-serial.log.gz)
