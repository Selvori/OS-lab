## 1. 任务要求与本次设计

已阅读 lab-5.pdf 全部7页，并核对第3至6页的地址空间、节点仓库、区间拆分合并与系统调用流程图。教学目标是让用户程序能够动态申请、释放堆内存，并理解参数如何经寄存器和 trapframe 到达内核。

课件要求 PCB 只保存 `mmap_region_t *mmap` 表头，节点包含 `begin/npages/next`；全局 `mmap_region_node_t list_mmap_region_node[N_MMAP]` 按需借出节点。链表描述**空闲**虚拟区：分配时从空闲区扣除，释放时插回并合并。节点不存放用户数据，也不代表连续物理内存。

本项目依据真实接口补充了明确选择：4096字节页、16MiB堆、128节点、系统调用5/6，以及错误码。课件没有给出这些值，也没有要求实现 libc 或完整POSIX接口。Lab4已实现通用ecall和带参数write，本次复用其正确路径。

`new → malloc → 系统调用` 是层次关系：用户态字节分配器可在这些页面上管理小对象。本次实现其底层按页内核服务；不把一个页接口称作完整malloc。

## 3. 地址空间、节点与不变量

```text
0x0000000000000000          空页，未映射
0x0000000000001000          一页代码，R/X/U
0x0000000000002000          一页数据，R/W/U
0x0000000000003000          USER_HEAP_START
          ...              4096页堆，按需建立R/W/U映射
0x0000000001003000          USER_HEAP_END（不包含）
          ...              未映射空隙，内核栈下方guard保留
0x0000003fffffc000          内核栈，U=0
0x0000003fffffd000          一页用户栈，R/W/U
0x0000003fffffe000          trapframe，U=0
0x0000003ffffff000          trampoline，R/X，U=0
```

`heap_top`由Lab4的初始堆标记改为固定堆上界。进程创建时只借出一个描述整个空闲区的节点，没有预分配16MiB物理页。使用全局节点仓库避免每个PCB都内嵌128节点；仓库用自旋锁保护，借出后节点由进程链表独占。

始终保持：

- 空闲区按地址升序，长度大于0，互不重叠，邻接区及时合并。
- 堆区内可用的RWU叶子页与空闲区互为补集，已分配物理页来自用户页池。
- 代码和内核特殊页不参与堆释放，堆不带X权限。
- 每个进程仍只由owner核访问；C代码在内核页表、关本核中断状态修改其私有映射。

## 4. 分配：查找、映射、提交

接口：`mmap(address, npages)`，以a0/a1传参，a7=5，返回a0。

1. 先检查页数非零、上界、页对齐，以及以除法和差值完成的无溢出范围检查。
2. address=0时查找第一个足够大的空闲区；非零时必须完整落入某个空闲区，绝不替换已有映射。
3. 若分配落在空闲区中部，先借出一个新节点留给右侧；借不到就返回-12，尚未改动任何映射。
4. 逐页从用户物理页池分配清零页面，建立R/W/U映射。物理页无须连续。
5. 全部映射成功后再修改空闲链表：前部移动begin，尾部缩小npages，中部保留左右两个节点，整块移除并回收节点。

例如原空闲区`[0x3000,0xb000)`，指定分配`[0x5000,0x7000)`后，链表变为`[0x3000,0x5000) → [0x7000,0xb000)`。再次首次适配时先利用低地址空洞，而非一直抬高堆顶。

任意页或页表分配失败，先释放尚未装入PTE的页面，剪除本次失败walk可能留下的空表，再撤销此前已成功建立的页。最后归还预留节点，原链表不变。不能只释放用户物理页而遗留中间页表。

## 5. 释放：预验证、撤销、合并

接口：`munmap(address, npages)`，a0/a1传参，a7=6，成功返回0。允许释放分配块的部分连续页，也允许跨相邻分配块，只要整个范围都是已映射堆页。

先验证完整范围：必须在堆内、页对齐、没有空洞或重复释放、每页是来自用户页池的RWU/NX叶子。然后查找左右空闲邻居：

| 邻接关系 | 链表操作 |
| --- | --- |
| 两侧均不相邻 | 预先借新节点，再按地址插入 |
| 仅左侧相邻 | 增加左节点长度 |
| 仅右侧相邻 | 右节点begin前移并增加长度 |
| 两侧相邻 | 合并三个范围，回收右节点 |

如果需要新节点但128节点均已借出，返回-12，页面仍归用户使用；合并不需要额外节点，即使仓库为空也可成功。

`vm_unmappages`也先验证整个范围，再逐页清除PTE、执行`sfence.vma`、归还物理页并调用`sv39_prune_empty`。后者只回收路径上完全为空的私有子表，保留根表和有其他映射的表。先撤销翻译再复用内存，避免旧TLB翻译继续访问已归还的页。

现阶段进程固定在owner核运行，其他核不持有或访问这个用户地址空间，故本地失效即可；未来迁移/并发访问必须重新设计锁和远程TLB失效。

## 6. 系统调用完整路径

```text
U-mode：a0=地址，a1=页数，a7=编号，执行ecall
  → 硬件进入S-mode并记录sepc/scause
  → trampoline user_vector保存整数寄存器到trapframe
  → 换为可信内核satp/sp/gp/tp，进入trap_user_handler
  → 对ecall将tf->epc增加4，syscall_dispatch读取保存的a7/a0/a1
  → user_heap_alloc或user_heap_free，结果写入保存的a0
  → trap_user_return准备内核返回信息、sstatus/sepc/stvec
  → trampoline恢复用户页表和整数寄存器，sret
  → 用户从ecall下一条指令继续，读取a0结果
```

RISC-V硬件对ecall保存的是**ecall自身地址**，不是自动保存下一条；本项目沿用Lab4的+4处理。普通时钟/外部中断保持epc。指针参数只是地址值，不能直接在内核解引用：原write仍先检查完整U/R权限，再通过物理恒等别名复制。

正式演示把字符串放在`0x3ff8`开始的跨页缓冲区，再调用write，证明大参数以指针+长度经寄存器进入内核且可安全跨页读取。错误码：-22非法参数/释放范围，-12资源或可用连续区不足；原-9/-14/-38分别保留为fd/用户指针/未知调用错误。

## 7. 进程生命周期与同步

主核在启动从核前初始化节点仓库；原started release/acquire发布全局初始化。页池和节点池各有自己的锁，节点池锁不覆盖页映射或整个syscall。私有空闲链表和页表没有并发修改者。

`proc_make_first → user_vm_create → user_heap_init → PROC_READY`。初始化失败统一经`proc_destroy`回滚。退出或用户故障先通过swtch回启动栈，清除current后才销毁：`user_heap_destroy`扫描有界堆区回收仍映射的页，归还全部空闲节点，随后释放原代码/数据/栈/tf和私有页表。

main比较进程前后的内核页池、用户页池与节点计数。正式用户程序最后刻意留下3页，让退出路径接受实际验证。Syscall在关中断状态同步完成；4096页上界限制工作量，但大操作仍会延迟本核中断，本阶段不提供实时延迟保证。
