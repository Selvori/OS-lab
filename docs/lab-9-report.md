# Lab 9 实验报告

## 任务

基于课程概览完成文件管理与用户态 Shell。项目和课程资料目录未取得该实验的独立课件和评分细则，ABI、容量、Shell 命令与程序格式采用自建 [规格](../patches/lab9.yaml)。

## 文件 ABI

系统调用保持 a7 编号、a0–a2 参数、a0 结果，错误返回负值。已有 `write`（1）扩展到文件描述符，仍保留单次 256 字节限制。启动时 fd 0 为输入、fd 1 和 2 为输出。

| 编号 | 调用 | 结果 |
| --- | --- | --- |
| 11 | open(path, flags) | 分配最低空闲 fd |
| 12 | read(fd, buf, n) | 读取至多 256 字节，返回实际数量，EOF 为 0 |
| 13、14 | close(fd)、dup(fd) | 关闭返回 0；dup 返回共享偏移的新 fd |
| 15、16 | fstat(fd, info)、readdir(fd, ent) | fstat 填充类型、大小和 inode；readdir 返回 1 或 EOF 0 |
| 17、18 | mkdir(path)、unlink(path) | 成功返回 0；现用的 inode 返回 -16 |
| 19、20 | chdir(path)、getcwd(buf, n) | 切换返回 0；读取返回不含结尾 NUL 的长度 |
| 21 | sync() | 同步块设备后返回 0 |
| 22 | exec(path, argv) | 成功进入新用户映像，失败返回负值 |

`include/kernel/file_abi.h` 定义读、写、读写模式及创建、截断和追加标志。每进程 16 个 fd，普通文件共享 48 个打开对象。每次独立 open 拥有独立偏移；fork 和 dup 增加引用，退出与用户故障释放引用。处于打开状态的 inode 及仍作为 cwd 的目录使用 -16 拒绝删除。读目标在 I/O 前验证全用户范围，写完整 copyin 后才访问文件；成功的字节数才推进偏移。

## 过程与架构

1. 从 `cc7ce84` 建立 Lab 9，先签署文件与进程接口规格。沿用 Lab 8 落盘布局，独立镜像生成目标保留 Lab 7/8 原镜像。
2. `kernel/fs/file.c` 连接进程描述符、共享打开对象、cwd 和已有 FS 接口。描述符状态由启动核独占，普通文件操作沿用 FS → block 锁顺序。
3. UART 中断将输入放入 512 字节队列，可来自任一 hart。无输入时进程放锁后睡眠一个时钟节拍，再检查队列；队列满时丢弃新字节。Shell 负责回显、取消和退格。回退程序继续使用原内核回显。
4. `kernel/proc/exec.c` 从 FS 读取头与单页程序，准备参数、栈和新堆元数据后再替换用户代码、数据、栈及寄存器。原代码页保持 RXU，内核经物理别名写入，返回前执行 `fence.i`。失败保留原执行上下文、堆、cwd 和打开文件。
5. `user/program.ld` 固定入口 `0x1000`，代码与常量不超过一页，程序不使用可写全局量。文件格式为 8 字节小端头，加上原始代码与常量。`mkfs.py --program NAME RAW` 在 `/bin` 写入程序，已存在的镜像保持不变。示例程序有 `sh` 和 `echo`。
6. 调整历史演示中非法 fd 的样例，从 2 改为 99，以适配 Lab 9 的 stderr。QEMU 运行完成后，使用旧镜像重复 Lab 6 正式和扩展场景，探针恢复后再次验证正式内核。

Shell 支持 255 字节输入和最多 12 个参数。exec 单参数最多 127 字节。当前范围为前台命令、基本文件操作与单页程序装载。管道、重定向、后台作业、通用 ELF 装载和权限系统留作后续扩展。SeeleFS 的 6144 字节单文件限制和断电恢复限制继续适用。

## 验证

- QEMU 5.1.0 真实串口，检查路径、读写、追加、引号、退格、长行、坏命令、坏执行文件及重启读取。
- 用户探针确认 16 个 fd 和 48 个打开对象耗尽及回收，fork/dup 共享偏移，坏用户地址不改变输出或偏移，子退出释放引用。exec 成功保留 fd 偏移及 cwd 并重建堆，失败保留原堆。
- 主机独立比较 520 字节跨扇区数据及位图。旧镜像的 [Lab 6 扩展回归](lab-9-evidence/lab6-extended.txt) 同时覆盖时钟抢占、进程失败回滚与 UART。
- `make -B CONFIG=riscv64-qemu-virt-sbi build` 和 VF2 `build image` 通过。入口 `0x80200000` 和 `0x40200000`，VF2 实机未验证。见 [验收结果](lab-9-evidence/results.json)。
